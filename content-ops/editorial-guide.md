# Brad Studio 콘텐츠 운영 지침

> 2026-10-04 확정. 애드센스 "Low value content" 거절 이후 방향 재정의.
> 글을 쓰거나 루틴이 초안을 만들 때 이 문서를 먼저 읽는다.

## 1. 포지셔닝

**AI를 소개하는 블로그가 아니라, AI 서비스의 가격·사용량·원가·UX를 실제 데이터로 뜯어보는 블로그.**

공개 데이터를 모아서 → 같은 기준으로 정규화하고 → 실제 돈이나 업무량으로 환산한 뒤 → 시장 구조가 어떻게 바뀌는지 해석한다.

"숫자는 있는데 감이 안 오는 정보"를 생활·업무 단위로 바꾼다.

- $10 → 원화 약 1만3천원
- 10,000 Token → 한글 약 몇 자
- 1,000 Credit → 실제 몇 원
- Agent 1회 → 업무 1건에 몇 원
- 월 사용량 → 작업 몇 회 가능

생활·재테크 글(기존 카테고리)도 같은 원칙을 따른다. 제도·가격을 내 돈 기준으로 환산한다.

## 2. 하루 구성 (재신청 전까지)

| 종류 | 개수 | 조건 |
|---|---|---|
| 연구형 데이터 글 (AI 가격·원가 시리즈 등) | 1 | 아래 5문항 중 4개 이상 충족 |
| 오래 가는 안내 글 (생활·재테크·튜토리얼) | 1 | 1년 뒤에도 유효, 직접 계산표 1개 이상 |
| 이슈 글 | 1 | 오래 가는 글 1개 이상으로 내부 링크, reviewAfter 필수 |

재신청 뒤에는 연구·안내 2 + 이슈 3까지 늘린다.

## 3. 주제 선정: 5문항 체크

1. 실제 공식 데이터가 있는가?
2. 여러 서비스(가능하면 10~20개)를 같은 기준으로 볼 수 있는가?
3. 독자가 숫자의 크기를 체감할 수 있는가?
4. 표나 차트로 보여줄 데이터가 있는가?
5. 조사 후 처음엔 안 보이던 인사이트가 하나 나오는가?

**4개 이상이면 작성.** 의견형 주제("AI가 업무를 바꾸는 이유", "유망 AI 서비스")는 쓰지 않는다.

우선 소재: Credit, Token, Runtime, Agent Run, Compute, Premium Request, Workflow Credit, Seat, API Usage, Context Window — 일반 사용자가 가격 구조를 바로 이해하기 어려운 단위.

## 4. 콘텐츠 축

| 영역 | 주요 소재 |
|---|---|
| AI SaaS 가격 | 플랜, Credit, Token, Agent 가격 |
| AI Unit Economics | 실제 원가, 작업당 비용, Heavy User |
| Freemium UX | 무료 플랜, Paywall, 업그레이드 유도 |
| AI Agent | Run, Runtime, Tool, Action, Compute |
| SaaS Pricing UX | Seat, Usage, Credit, Hybrid |

### 시리즈 흐름 (AI SaaS Economics)

1. SaaS 11개 가격표 비교 — 무료 플랜은 어디까지 무료일까
2. AI 기능은 SaaS 가격을 어떻게 바꾸나 — Seat → Credit·Usage
3. AI SaaS 원가를 업무 단위로 — GPT·Claude·Gemini Token 환산
4. AI 서비스 10개 Credit의 원화 가치
5. 15개 서비스 Paywall 분석 — 무료 사용자를 어디서 막나
6. AI Agent 1회 실행 비용 — 10개 서비스 비교

**네이버 블로그와 중복 금지.** 같은 글을 그대로 옮기면 애드센스·구글 검색에서 복제 콘텐츠로 본다. 이 블로그에는 조사일을 새로 잡아 데이터를 갱신하고, 표·계산·결론을 새로 쓴 버전만 올린다. 원문이 네이버에 있으면 canonical 대신 "이전 조사(날짜)와 달라진 점" 섹션으로 차별화한다.

## 5. 글 구성

1. **제목**: 숫자 + 대상 + 행동 + 결과, 또는 질문 + 조사 범위.
   - 예: "AI Agent 한 번 실행하는 데 얼마일까? 10개 서비스를 비교해봤다"
   - `최신`, `충격`, `무조건`, `대박` 금지.
2. **도입** 3단: 변화가 생겼다 → 가격표로는 이해가 어렵다 → 그래서 조사했다.
3. **조사 기준 박스** (필수, 도입 직후)
   - 조사일 / 조사 대상 수 / 자료(공식 Pricing Page·Help Center) / 환율(기준일 명시)
   - 비교가 완벽하지 않은 이유
4. **본론**: 데이터 표 → 체감 단위 환산 → 해석.
5. **결론**: 앞 내용 반복 금지. 가격 구조 변화를 한 단계 위에서 해석한 Edge Insight 하나.
   - 예: "AI Credit은 화폐가 아니라 서비스 내부의 원가 추상화 단위다."

## 6. 데이터 기준

- **숫자는 세 종류로 구분해 표기한다.**
  - 공식 공개값: 회사가 공개한 가격 (출처 링크)
  - 단순 계산값: 공식값을 나눈 값
  - 가정 기반 시뮬레이션: 시나리오를 밝히고 범위로 표기
  - 세 가지를 섞어 실제 가격처럼 쓰지 않는다.
- **체감 단위 변환 순서**: 공식 단위 → 실제 작업 → 원화.
- **억지 비교 금지**: 이름이 같아도(Notion·Figma·ClickUp Credit) 단위가 다르면 "직접 비교할 수 없다"를 결론으로 쓴다.
- 확인 안 된 숫자는 넣지 않는다. 출처 접근이 막히면 해당 수치를 빼고 쓴다.
- frontmatter `sources`에 공식 페이지 URL과 accessedAt(조사일)을 모두 남긴다.

## 7. 문체

- 산문형 문단, 한 문단 2~5문장. 문장마다 줄바꿈하지 않는다. 논점이 바뀔 때만 줄바꿈.
- 업계 용어(Credit, Token, Runtime, Agent, Workflow, Tool Call, Context, Seat, API, Paywall, Heavy User, Unit Economics)는 번역하지 않는다. 처음 나올 때 한국어 설명을 붙인다.
  - 예: "Runtime, 즉 Agent가 실제 컴퓨터 환경을 사용한 시간"
- 금지어 (A등급): 따라서 / 이를 통해 / 이를 바탕으로 / 뿐만 아니라 / 무엇보다 / 결과적으로 / 결국에는 / 이와 같이 / 다시 말해 / 또한 / 그러므로 / 이로써 / 이러한 경험은 ~계기가 되었다 / 이를 계기로 / 이러한 과정을 통해 / 종합해보면 / 그러한 점에서 / 한편 / 결국 말하자면 / 요컨대 / 덧붙여 말하면 / 다시금 / 앞서 언급한 것처럼 / 결국 ~하게 되었다 / 그러다 보니
- 연결어 대신 행동·맥락으로 잇고, 수동태보다 능동태.

## 8. 이미지

텍스트보다 이미지가 빨리 이해되는 부분만. 한 글에 2~5장.

- 종류: 구조도(Chat vs Agent 비용 구조), 비교표, 막대그래프, 매트릭스(서비스 × Paywall 유형), 숫자 카드(핵심 결과 3~5개)
- 스타일: 흰 배경, Navy 헤더, Blue/Green/Purple/Orange 포인트, Rounded Card, 장식 최소화, 데이터 인포그래픽
- 모바일에서 읽히는 큰 글자, 표 안 긴 설명 금지
- 글자와 박스가 겹치지 않게 여백 확보. 표가 길면 내용을 줄이거나 높이를 늘린다.
- 직접 만든 이미지는 `public/images/<contentId>/`에 두고 alt를 구체적으로 쓴다. 썸네일은 기존처럼 Unsplash 또는 직접 만든 숫자 카드.

## 9. 발행 전 체크

- [ ] 5문항 중 4개 이상
- [ ] 조사 기준 박스 (조사일·대상·자료·환율)
- [ ] 숫자 3종 구분, 체감 단위 환산
- [ ] 이미지 2~5장, 겹침 없음
- [ ] 결론에 Edge Insight 하나, 요약 반복 없음
- [ ] 금지어 0건
- [ ] 내부 링크 2개 이상, sources 기록
- [ ] 네이버 원문과 중복 아님 (데이터·문장 새로 작성)
